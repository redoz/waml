# OKF v0.2 reader — implementation plan

**Design:** `docs/superpowers/specs/2026-08-05-okf-v0-2-reader-design.md` (authoritative)
**Spec:** `docs/specs/OKF_SPEC.md` §5, §7, §11, §13

Six tasks. Each is independently committable, compiles, and leaves
`cargo test --workspace` green. No task needs the `editors/vscode`
test/lint/build: no TypeScript reads any of these fields (the design's Risks
section verifies this), so the vscode gate is unaffected by every task —
run it if the harness runs it anyway, but nothing here can move it.

Files touched across the plan:

- `crates/waml/src/okf.rs` — types, `trust_tier()`, unit tests
- `crates/waml/src/okf/shell.rs` — frontmatter promotion, legacy body parsing
- `docs/waml/architecture/concepts/model/okf-bundle.md` — version note

Not touched, deliberately: `serde_shape.rs`, any serde derive or attribute on
existing types, every v0.1 fixture document. New types carry the same
`cfg_attr(feature = "serde", derive(...))` derives as their neighbours
(`Link` is the template) — nothing more.

## The promotion-success rule (applies to Tasks 2–4)

`Concept`'s doc comment promises the projection is lossless. Today
`shell.rs` builds `extra` by filtering out every key named in `KNOWN_KEYS`
(`project_concept`, the `extra` construction around `shell.rs:322`). That is
wrong for the new keys: a `sources` that is not a list would vanish — neither
promoted nor kept.

Concrete mechanism, introduced in Task 2 and reused by Tasks 3–4: each new
key's promotion function returns `Option<T>` (or `Vec<T>` plus a succeeded
flag where the whole-key promotion is all-or-nothing per the design's
malformed table). `project_concept` collects the set of keys whose promotion
**actually succeeded** into a `promoted: BTreeSet<&str>` (seeded with the
v0.1 `KNOWN_KEYS`, whose behaviour is unchanged — see Concerns), and the
`extra` filter becomes `!promoted.contains(key)` instead of
`!KNOWN_KEYS.contains(key)`. "Succeeded" is per the design's table:

| Key | Succeeded means | On failure |
|---|---|---|
| `sources` | value is a list; at least the list shape held (see Task 2 for per-entry skips) | key stays in `extra` |
| `usage_window` | value is a map with recognizable `from`/`to` strings | key stays in `extra` |
| `generated` | map with a `by` that parses as an actor | stays `None`, key stays in `extra` |
| `verified` | list (or bare map) where at least the shape held; entries without `by` are skipped | key stays in `extra` |
| `status` | value is one of `draft`/`stable`/`deprecated` | falls back to `Stable`, key stays in `extra` |

Per-entry granularity inside `sources`: an entry missing `resource` is
skipped but the **whole raw `sources` value** stays in `extra` whenever any
entry was skipped or malformed — a partially-promoted list must not drop the
entries it declined. When every entry promoted cleanly, the key leaves
`extra`. Same rule for `verified`. This is the testable statement of "a key
leaves `extra` only when its promotion actually succeeded".

No new `BundleError` variant anywhere in this plan.

### Task 1: Replace `Citation` with `Source`

**Files:** `crates/waml/src/okf.rs`, `crates/waml/src/okf/shell.rs`

**Changes:**

- In `okf.rs`: delete `Citation`. Add `UsageWindow { from: Option<String>, to: Option<String> }`
  and `Source { id, resource: String, title, author: Option<Actor>… }` exactly
  as the design's Rust block gives them — except `author`, which needs `Actor`
  from Task 3. To keep Task 1 self-contained, add `Actor { kind: Option<String>, id: String }`
  here too (type only, no promotion logic yet; Task 3 adds its parser and the
  types that use it). All three carry `#[derive(Debug, Clone, PartialEq)]` and
  the neighbourly `cfg_attr` serde derives, matching `Link`.
- Rename `Concept::citations: Vec<Citation>` to `Concept::sources: Vec<Source>`
  (same `skip_serializing_if = "Vec::is_empty"` attribute shape as before).
- In `shell.rs`: `extract_citations` becomes `extract_legacy_sources`,
  producing `Source { resource: link.destination, title: Some(link text), .. }`
  with every other field `None`/absent. `project_concept` populates
  `sources` from it. The `Citation` import goes away.
- Doc comments: `Source` cites OKF §5.1; the legacy mapping is documented on
  `extract_legacy_sources` (v0.1 `# Citations` entry ⇒ absent credibility
  signals; no origin tag).

**Tests** (in `okf.rs` `mod tests`):

- `non_uml_doc_round_trips_every_field_onto_concept` and
  `concept_links_and_citations_follow_authoritative_markdown_queries` update
  mechanically: `.citations` → `.sources`, and the citation assertions now
  check `resource`/`title` on `Source`. The fixture *documents* inside them
  are byte-for-byte unchanged — that is the dual-read proof for the body-list
  path. Rename the second test to
  `concept_links_and_sources_follow_authoritative_markdown_queries`.
- New: `legacy_citation_maps_to_source_with_absent_signals` — a v0.1
  document with a `# Citations` list projects `Source` entries whose `id`,
  `author`, `usage_count`, `last_modified`, `usage_window` are all `None`,
  and whose `title` is the link text.

**Gate:** `cargo test --workspace`. The `serde_shape.rs` OKF assertions never
mention `citations` (design Risks), so they pass untouched — if they do not,
stop: that is a design-risk falsification, not something to patch around.

### Task 2: Promote frontmatter `sources` with precedence and the success-tracked `extra`

**Files:** `crates/waml/src/okf/shell.rs`, `crates/waml/src/okf.rs` (tests)

**Changes:**

- Add `"sources"` and `"usage_window"` handling to `project_concept` via a
  new `promote_sources(fm: &Frontmatter) -> Option<Vec<Source>>` helper
  (returns `None` when the key is absent or its promotion failed; the flag
  distinguishing "clean" from "partial" drives the `extra` decision per the
  promotion-success rule above).
- Entry promotion: an entry must be an `FmValue::Map` and carry a `resource`
  string, else it is skipped. `id`, `title`, `last_modified` are plain
  strings via the map's entries; `usage_count` accepts only `FmValue::Num`
  (an `f64`, matching the design's `Option<f64>`); `author` is deferred —
  in this task the field is built as `None` unconditionally (Task 3 wires
  the actor parser in). `usage_window` (entry-level and sibling) is a map of
  `from`/`to` strings.
- Sibling `usage_window` resolution: after entry promotion, every `Source`
  lacking its own `usage_window` receives a clone of the sibling one, so a
  consumer never looks outside the `Source` it holds.
- **Precedence:** when `promote_sources` yields entries (the key exists as a
  list), `extract_legacy_sources` is not called. The body `# Citations`
  heading is parsed only when the `sources` key is absent. When `sources`
  exists but its promotion failed wholesale (not a list), it is treated as
  absent for precedence — the legacy list still parses, and the raw value
  stays in `extra`. The heading text remains verbatim in `Concept::body`
  either way (no body change is made at all).
- Introduce the `promoted` set mechanism described above; `KNOWN_KEYS` grows
  `"sources"` and `"usage_window"` **only as documentation of the v0.2
  vocabulary** — the `extra` filter now reads from the `promoted` set, not
  from `KNOWN_KEYS` membership. (If after Task 4 `KNOWN_KEYS` has no reader
  left, delete the constant in that task rather than keeping a dead list.)

**Tests** (in `okf.rs`):

- `frontmatter_sources_promote_with_all_signals` — a document whose
  `sources` entries carry `id`, `resource`, `title`, `usage_count`,
  `last_modified` and a sibling `usage_window`; asserts every field, and that
  neither `sources` nor `usage_window` remains in `extra`.
- `frontmatter_sources_take_precedence_over_citations_heading` — both
  syntaxes present; only the frontmatter entries appear in
  `Concept::sources`, and `body` still contains `# Citations`.
- `sibling_usage_window_fills_entries_and_entry_window_overrides` — two
  entries, one with its own window; asserts the fill and the override.
- `sources_entry_without_resource_is_skipped_and_raw_value_survives` — a
  two-entry list where one entry lacks `resource`: the good entry promotes,
  and `extra.get("sources")` is still `Some` (partial promotion keeps the
  raw value).
- `sources_that_is_not_a_list_promotes_nothing_and_survives_in_extra` —
  `sources: oops` yields no `Source` from frontmatter, the legacy body list
  (if present) still parses, and `extra.get_str("sources")` is
  `Some("oops")`.
- `usage_count_that_is_not_a_number_stays_none_and_list_survives` — per the
  malformed table: the entry still promotes (with `usage_count: None`) but
  the raw `sources` stays in `extra` because promotion was not clean.

**Gate:** `cargo test --workspace`.

### Task 3: `Actor`, `Generated`, `Verification` — promote `generated` and `verified`

**Files:** `crates/waml/src/okf.rs` (types, tests), `crates/waml/src/okf/shell.rs`

**Changes:**

- In `okf.rs`: add `Generated { by: Actor, at: Option<String> }` and
  `Verification { by: Actor, at: Option<String> }` with the neighbourly
  derives (Actor itself landed in Task 1). Add `Concept::generated: Option<Generated>`
  and `Concept::verified: Vec<Verification>` with the same
  `skip_serializing_if` shapes as their `Option`/`Vec` neighbours.
  `Concept::timestamp` stays exactly as it is (v0.1 retained).
- Actor parsing (`shell.rs`, a small `parse_actor(&str) -> Actor` — it is
  infallible: `human:ahormati` ⇒ `kind: Some("human"), id: "ahormati"`;
  a bare id ⇒ `kind: None`. Split on the **first** `:` only; an empty id
  side after the split still yields an `Actor` faithful to what was written
  (per §7 the prefix is a convention, not a validation gate).
- `promote_generated`: requires an `FmValue::Map` with a string `by`
  (actor-parsed); `at` optional string. Missing/`by`-less ⇒ `None`, raw
  value stays in `extra`. **Fallback (§13.1):** `Concept::generated` is
  promoted only from the `generated` key. A synthesized `Generated` for a
  v0.1 document cannot exist — `by` is REQUIRED and a v0.1 document names
  no actor — so the fallback is a **reader-side accessor**:
  `impl Concept { pub fn generated_at(&self) -> Option<&str> }` returning
  `generated.at` or else `timestamp`. `Concept::generated` itself stays
  `None` for a pure-v0.1 document. (See Concerns — the design prose is
  one line here and this is the only reading consistent with `by: Actor`
  being non-optional.)
- `promote_verified`: accepts `FmValue::List` of maps *or* one bare
  `FmValue::Map` (normalized to a one-element list — §5.2 MUST). Entries
  without a parseable `by` string are skipped. Clean promotion removes the
  key from `extra`; any skipped entry or a non-list/non-map value keeps the
  raw value in `extra` (and a non-list/non-map promotes nothing).

**Tests** (in `okf.rs`):

- `generated_promotes_by_and_at` — actor prefix split asserted
  (`process:finance-nightly` ⇒ kind/id), `at` carried, key gone from `extra`.
- `generated_without_by_stays_none_and_survives_in_extra`.
- `generated_at_falls_back_to_timestamp_for_v01` — a v0.1 document:
  `generated` is `None`, `timestamp` populated, `generated_at()` returns the
  timestamp; a v0.2 document with both prefers `generated.at`.
- `bare_verified_mapping_normalizes_to_one_element`.
- `verified_entry_without_by_is_skipped_and_raw_value_survives` — one good,
  one `by`-less entry: one `Verification` promoted, `extra` keeps `verified`.
- `bare_actor_id_has_no_kind` — `by: finance-nightly` ⇒
  `Actor { kind: None, id: "finance-nightly" }`.
- Task 2 follow-through: `promote_sources` now parses `author` through
  `parse_actor` instead of leaving `None`; extend
  `frontmatter_sources_promote_with_all_signals` to assert `author`.

**Gate:** `cargo test --workspace`.

### Task 4: `Status` and `stale_after`

**Files:** `crates/waml/src/okf.rs` (types, tests), `crates/waml/src/okf/shell.rs`

**Changes:**

- In `okf.rs`: `pub enum Status { Draft, Stable, Deprecated }` with
  `impl Default for Status { Stable }` (or `#[derive(Default)]` with
  `#[default]`), neighbourly derives. Add `Concept::status: Status`
  (serde: `default`, and `skip_serializing_if` on `== Status::Stable` is a
  serde-surface choice — since the surface is untouched policy, serialize it
  plainly with `default` only, mirroring how `ty` is always present; do NOT
  add new custom skip helpers) and `Concept::stale_after: Option<String>`
  (same attribute shape as `timestamp`).
- `shell.rs`: promote `status` by exact lowercase token match on the three
  spellings from §5.4; anything else ⇒ `Status::Stable` (the §5.4 default)
  **and** the raw value stays in `extra` (absent key also ⇒ `Stable`, with
  nothing in `extra` to keep). Promote `stale_after` as a plain string —
  it stays a raw date; **no `is_stale()` helper exists or is added**
  (headless crate, no clock, `SystemTime::now()` panics on wasm — the doc
  comment on the field says a caller passes today's date).
- If `KNOWN_KEYS` is now unread (the `promoted`-set filter replaced it in
  Task 2), delete it here; otherwise it lists the full v0.2 vocabulary.

**Tests** (in `okf.rs`):

- `status_promotes_three_tokens_and_defaults_to_stable` — `draft`, `stable`,
  `deprecated`, and absent-key ⇒ `Stable`.
- `unknown_status_falls_back_to_stable_and_survives_in_extra` —
  `status: experimental` ⇒ `Status::Stable` and
  `extra.get_str("status") == Some("experimental")`.
- `stale_after_promotes_as_raw_string` — value carried verbatim. The
  absence of `is_stale` is enforced by never writing it; no test can assert
  a method's non-existence.

**Gate:** `cargo test --workspace`.

## Out of scope (do not implement, do not "prepare for")

- Attested Computation (§10): `runtime`, `parameters`, `computation`,
  `executor`, `attester` keys and the `# Computation` heading — all stay
  untyped in `Concept::extra` and unparsed in `body`.
- Per-claim footnote attribution (§5.1).
- Any change to the serde surface, `serde_shape.rs`, or the derives on
  existing types.
- Any `is_stale()` / clock-touching helper.
- Any new `BundleError` variant.

## Concerns

1. **The `generated.at` ⇒ `timestamp` fallback is under-specified in the
   design.** The design lists it as a bullet ("`generated.at` falls back to
   `timestamp` when `generated` is absent") but also makes `Generated::by`
   a non-optional `Actor`, and a v0.1 document names no actor — so a
   synthesized `Generated` value cannot exist. Task 3 resolves this as a
   reader-side accessor (`Concept::generated_at()`) rather than fabricating
   an actor. If the design intended `Concept::generated` itself to be
   populated for v0.1 documents, `Generated::by` would need to become
   `Option<Actor>`, which contradicts §5.2's "REQUIRED within `generated`".
   The accessor reading is planned; flagging in case the intent differed.
2. **Old-key `extra` behaviour is left as-is.** The promotion-success rule
   is applied to the new v0.2 keys only. The v0.1 keys keep today's
   behaviour (e.g. `title: 123` is filtered from `extra` even though
   `get_str` declined it) because changing it is outside the design's scope
   and risks the "existing tests unmodified" requirement. The same lossless
   argument applies to them, though — a natural follow-up spec.
3. **Task 1 must rename two existing unit tests' field accesses.** The
   instruction "existing v0.1 fixtures and tests stay unmodified" cannot
   hold literally for tests that name the deleted `citations` field; the
   fixture *documents* inside them are byte-identical, and only the
   accessor/assertion side changes mechanically. Called out so the review
   does not read the diff as fixture drift.
4. **Partial-promotion `extra` semantics are my concretization.** The design
   says a key leaves `extra` only when promotion "actually succeeded" and
   separately that a skipped entry's raw value survives; for a list where
   one entry fails, the only representation that keeps the skipped entry is
   keeping the whole raw list in `extra` while still promoting the good
   entries. That duplication (a good entry appears both promoted and inside
   the raw `extra` value) is inherent to the design's two promises and is
   asserted as such in the Task 2/3 tests.
