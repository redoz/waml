# WAML Audit — Consolidated Report

*Editor-in-chief synthesis of 9 panel reports, revised after adversarial red-team review. Spot-checks marked **(verified)** were re-confirmed against the repo at HEAD (a6a267e2, 2026-08-20) during synthesis; red-team corrections were re-verified against the repo before incorporation.*

---

## 1. Executive verdict

WAML is a genuinely well-engineered codebase attached to a product that nobody can install, whose trust layer lies, and whose only defined user is itself. The engineering is not the problem: the crate DAG is a strict, correctly-oriented layering; the edit model is transactionally sound with diff-derived undo; the incremental parser has proptest+fuzz+conformance coverage at rust-analyzer grade; a native GUI crate carries ~1,400 inline unit tests via disciplined pure-geometry separation; and issues.md plus the goals scoreboard are the most honest self-assessment artifacts any panel had seen at this scale. But the product facts are brutal. Zero release tags exist **(verified)** — there is no way to obtain the native editor. The trust layer fails in two distinct ways **(both verified)**: the public compat entry points `validate()`/`validate_from_source()` convert analysis failure into an empty, *successful* result (crates/waml/src/validate.rs:17,38,41), and the CLI `check` path — which does correctly exit 2 when `prepare` fails — projects diagnostics from `candidate.uml().diagnostics` *only* (validate.rs:51-67), while analysis.rs:135-139 quarantines shell-failed documents with a doc-comment promising "consumers surface these as per-document diagnostics" and no consumer on the check path does. A bundle containing a document the parser could not even shell-parse passes `waml check` with exit 0 and zero output. This "trust the content" pillar was filed as P1 on 2026-07-31; no commit since implements the fix (validate.rs was touched once by a routing refactor, 08ab758c, and a diagnostic-provenance fix landed elsewhere, 354f7887 — neither builds the aggregate stream) while ~2,075 commits of Mermaid rendering, book mode, use-case diagrams, and search landed around it. Worse, the CI documentation contract the project rightly prizes gates through this exact command (`waml-cli check docs/waml`, ci.yml:67-73) — the flagship honesty mechanism is certified by the component proven untruthful. issues.md itself froze on 2026-08-05 **(verified)** and now lists a fixed P1 next to a still-live P1 silent-data-loss bug (`FieldEdit::Unchanged` serializes to the same wire bytes as `Clear` and deserializes back as `Clear` — **verified live**, crates/waml/src/uml/ops.rs). The fuzz safety net has been red for its last two weekly runs **(verified via gh run list, both dead at 25–27s)** on a compound toolchain failure — taiki-e/install-action binstalls a musl-hosted cargo-fuzz that then targets x86_64-unknown-linux-musl, hitting both the ASAN×static-libc incompatibility *and* a missing musl std — meaning no fuzzing has executed for weeks. Rendering has no automated regression gate at all, and the flagship "zero-install reader" paints all text onto a GPU canvas: invisible to screen readers, browser find, and search engines — a product-defining gap for a knowledge tool whose source format is Markdown. There is no dependency auditing anywhere, and every GUI build — CI, Pages deploy, tooling install — routes through one personal GitHub account. Meanwhile the codebase's own written laws are broken in two load-bearing places: the okf.rs header promises a mechanical okf-core split while `Index` embeds a `ViewDecl` and `resolved_view` takes the middleware registry **(verified: okf.rs:5-8 vs :394, :556-559)**, and the makepad fork SHA is hand-copied into five manifest entries with a *different* SHA in pages.yml **(verified)**. The strategy question the docs conspicuously avoid: this is three company-sized products (language toolchain, from-scratch GUI editor with its own text engine, research-grade layout solver) stapled together by a fourth (a forked UI framework), built by exactly one person (2,833/2,833 public commits), for a user who has never been identified. Every MVP area is "partial." The foundations will scale; the current allocation of effort will not converge.

## 2. What is genuinely strong

These are not compliments; they are assets that the top actions assume you keep. Where an asset has an asterisk, it is attached here, at the point of praise.

- **The edit/undo model is provably sound.** Forward edits are pure bundle→bundle lowerings and the inverse is *derived by diffing* (`SourceDelta::between`, crates/waml/src/edit/mod.rs:99-106), so undo cannot desync from the applied edit. Inverse splices are preimage-checked (edit/reversible.rs:117-147), late-step failure publishes neither source nor inverse (batch.rs test at :584), and mixed OKF/UML batches synchronize through an explicit `Invalidation` seam (batch.rs:70-95).
- **The syntax pipeline is real compiler engineering.** One Markdown parse in the whole system; pulldown-cmark quarantined behind a scan seam with a build-failing test (crates/waml-syntax/src/markdown/scan/pulldown.rs:1-4, tests/scan_seam.rs); typed CST wrappers → Declared layer with per-field validity (uml/declared.rs:12-50) → semantic model → structured DiagCode diagnostics. CommonMark 0.31.2 + GFM conformance fixtures, proptest incremental-vs-full fingerprint equivalence, committed proptest-regressions, four libFuzzer targets on the scariest surfaces.
- **Cross-crate layering is a strict DAG with correct arrows.** waml-syntax knows nothing above it; waml-markdown-editor depends only on waml-syntax + makepad with *zero* platform cfgs and communicates upward through host traits (presentation/assets.rs:33, presentation/highlight.rs:109); crates/waml has no makepad dependency; the vscode extension is a pure LSP-over-stdio process seam with zero TS-side language logic (editors/vscode/src, 3 files).
- **The editor shell architecture is right.** One `OpenDocument`/`DocView` abstraction across all ten surface kinds; views return `ViewOutcome` intents and only the shell applies edits/opens tabs/places popups, consumed at exactly one site (app/actions.rs:1872-1989); dispatch order is const arrays with order-pinning tests (actions.rs:2147, :2162); exactly two popup/overlay mechanisms; 1,439 `#[test]` functions inside src/ from systematic no-Cx pure-geometry separation.
- **The projection middleware chain is the best abstraction in the codebase.** CPS-style `Next` with a terminal `RootView` so "no view declared" and "chain tail" are one code path; the `occludes()` hook documents and closes the exact filter-bypass hole a naive dispatch would open (crates/waml/src/view/projection.rs:69-143).
- **The web delivery loop is a finished, differentiated deliverable — with one product-defining asterisk.** Every push to main builds and deploys the wasm editor gated on full CI (9 consecutive green Pages runs); boot driven 40s→~1.7s by real engineering; `waml export site` produces a zero-server, zero-install reader with share-URL model persistence (README.md:51-71). Nothing in the Mermaid/PlantUML/Structurizr set does "reviewable model in the PR + zero-install reader" as one loop. *Asterisk:* the exported site **is** the embedded wasm editor painting text onto a GPU canvas (crates/waml-cli/src/site.rs:1-10) — zero screen-reader accessibility, no browser find, no text indexing — while the competitor set ships accessible HTML. See §4.
- **Self-assessment culture — with two asterisks.** issues.md (1,085 lines: priorities, dismissed findings, a do-not-fix list, sequenced roadmap), an evidence-derived MVP scoreboard that honestly reports every area "partial" and records its own scope violations (docs/waml/goals/mvp.md, BHV-BRW-014), and a CI-enforced documentation contract dogfooding docs/waml as a live bundle. Zero TODO/FIXME/HACK markers across ~190k lines of the two main crates. *Asterisks:* (1) the doc contract's gate is `waml-cli check docs/waml` (ci.yml:67-73) — the exact command whose diagnostic projection drops everything but `uml().diagnostics` and silently swallows quarantined documents, so the contract can pass green while docs/waml contains documents the parser couldn't shell-parse; fixing the trust layer will likely surface a wave of latent doc-contract failures, a pattern this project has already lived once (the 3-day masked gate). (2) issues.md has been frozen for 15 days through heavy landing and now mixes fixed and live P1s (§3.4).

## 3. Architecture

### 3.1 Structure & layering

The vertical layering is excellent; the horizontal problems are hubs, dumping grounds, and hand-maintained parallel lists.

- **okf substrate layering is broken against its own written law** **(verified)**. okf.rs:5-8 declares the substrate MUST NOT import UML types so "a later okf-core crate split stays mechanical." But `okf::Index` embeds `crate::view::decl::ViewDecl` (okf.rs:394), `Bundle::resolved_view` takes `view::chain::MiddlewareRegistry` (okf.rs:556-559), view/chain.rs imports okf back (cycle), and view/kind.rs:5 imports `crate::model::{BehaviorKind, ElementType, UmlMetaclass}`. The substrate transitively depends on the UML model *today*. The direct-import rule inside okf files does hold (grep confirms only doc-comments mention the forbidden names) — the violation is transitive, which is exactly the kind a header comment can't see.
- **analysis.rs is a hub, not a layer.** It hard-codes the UML specialization (analysis.rs:610/624/773), back-patches a UML-derived `code_syntax` map into the supposedly domain-agnostic `OkfAnalysis` (attach_code_syntax, :250-255), and owns `DocumentId`, dragging diagnostic.rs and edit/ into mutual dependency. 116 files couple to it.
- **uml/analysis.rs is the crate's one true dumping ground.** 4,610 lines, 117 functions, tests only at :4580; `declared_projection` is 415 lines, `validate_declared_semantics` 405, interleaving extraction, validation, projection, and orchestration. The named "god files" elsewhere (frontmatter.rs, okf.rs, model.rs) are mostly false alarms — cohesive modules inflated by inline tests.
- **App is a 54-field god object** (tokensave god_class rank #3; app.rs:774) whose impl spans seven files (~7,800 lines), absorbing every feature's residual state — palette query, find sessions, menu-subject keys, wheel-zoom targets. The dispatch is explicit and test-pinned, which is why it still works, but the growth is strictly linear accretion into one type.
- **The layout solver has no facade.** All 13 solve/ submodules are `pub mod`; the editor reaches into VPSC `Sep` types, `StressConfig`, route clipping, and label internals across 15 distinct entry points (scene.rs:727, :1212, :2491, canvas/class/render/labels.rs:370-376). scene.rs (3,465 lines) keeps three parallel edge lists synced "by construction" with a route cursor whose own comments admit the lists can desync (scene.rs:1141-1186), guarded only by a `debug_assert`.
- **The editor src root is a flat junk drawer**: 100 files, 103 mod declarations, with directory-shaped clusters (book_*, folder_*, tree_*, *_overlay) that aren't directories, and four modules competing for the name "navigation."

### 3.2 Seams & boundaries

- **The makepad fork seam is controlled by discipline, not mechanism** **(verified)**. Rev 6534634a is hand-copied into 5 dependency entries across 4 manifests (waml-editor, waml-markdown-editor, waml-ui-test ×2, workspace unicode-bidi) — and makepad-widgets is *not* a `[workspace.dependencies]` entry even though unicode-bidi on the same fork/rev is, proving the mechanism was available and unused. pages.yml pins cargo-makepad to a *different* SHA (62f515dc, pages.yml:81) held in step only by a prose comment. The fork carries 44 commits / +2992−563 of divergence including WAML-domain behavior (fragment anchors, scroll anchors, semantic test items, a `wip:` DComp commit baked into the pinned lineage), inventoried nowhere but a 28-line Cargo.toml comment.
- **Supply-chain posture is zero** **(verified)**. No cargo-audit or cargo-deny runs anywhere in .github/workflows/, no deny.toml exists — RUSTSEC advisories in the lockfile go unseen. All four GUI-adjacent crates take git dependencies on github.com/redoz/makepad (Cargo.toml:24, waml-editor:39, waml-markdown-editor:11, waml-ui-test:10-11), and pages.yml:77-81 `cargo install --git`s cargo-makepad from the same personal fork — build tooling that then executes in CI with deploy permissions. If that account or repo is compromised, deleted, or force-pushed, every build fails or (rev pins mitigating, but the tooling install path is the live risk) pulls attacker code. GitHub Actions are tag-pinned — mutable references (checkout@v7, Swatinem/rust-cache@v2, taiki-e/install-action) — not SHA-pinned.
- **No third-party license attribution for the distributed bundle** **(verified)**. The repo is MPL-2.0, but the Pages site and every `waml export site` output distribute compiled MIT code (the entire makepad fork; C:/dev/makepad/LICENSE = MIT) plus merman (`MIT OR Apache-2.0`). MIT's one obligation is that the notice accompany substantial portions; there is no NOTICE, THIRD-PARTY file, or license page anywhere in the repo or in site.rs's asset list. Cheap to fix, embarrassing to be caught missing — and this project has already gone through a deliberate relicense-and-history-purge, so it demonstrably cares about exactly this.
- **The HTTP wire contract is split-brain** **(verified)**. waml-ops-dto exists to be the shared contract, but only the inner `DocumentWrite` lives there. The envelope is defined twice as structurally-unlinked serde types: `DocumentsRequestWire` in crates/waml-editor/src/api_save.rs:20 with hand-rolled response parsers (:58, :70) vs `DocumentsRequest`/`DocumentsResponse` in crates/waml-cli/src/serve/routes.rs:220/226. A field rename compiles green on both sides and breaks at runtime. Relatedly, waml-ops-dto depends on the full waml crate — it is a protocol module, not a decoupling boundary; fine, but stop calling it a seam.
- **Platform variance has no consistent pattern**: 155 `target_arch` cfgs across 16 editor files; markdown_extensions/mod.rs alone (1,303 lines, 53 cfgs) interleaves a native worker pool with the wasm path. The trait-adapter pattern exists (platform_browser.rs) and is used for exactly one concern.
- **The LSP advertises FULL sync** (lsp/server.rs:64-68) then reverse-engineers a diff the client already had (analysis.rs:1331) — the one consumer where incremental sync is a free protocol feature doesn't use it, despite the entire `&[TextChange]` machinery existing and being tested.
- **Manifest honesty**: waml-editor's description says "read-only GPU viewer" while shipping two write backends. (The workspace-1.80 vs waml-editor-1.95 MSRV split, flagged in an earlier draft, is *not* a defect: per-crate `rust-version` overrides are the intended cargo mechanism, and waml-editor explicitly declares its own requirement.)
- What is *not* wrong: the embed-web build seam degrades gracefully (waml-cli/build.rs:20-45), and the LSP's document-state machine handles open-generation/version races correctly with tests (bundle.rs:153-181, :639-:723). **Serve security is competent with one caveat**: the token work is genuinely good — CSPRNG bearer token, constant-time compare, loopback default, anti-rebinding Host check, origin check (guard.rs:1-40) — but the token is accepted as, and by design printed in, a `?token=` query parameter (guard.rs:8-11; routes.rs handlers take `Query(token_q)`), so it lands in browser history; and under `--bind-all` it traverses the LAN in plaintext http URLs with the Host/origin checks explicitly relaxed (guard.rs:112-135; serve/mod.rs:24). No TLS exists anywhere in serve/. Jupyter-style and defensible for loopback — but the caveat belongs next to the clean bill.

### 3.4 Quality & tests

The logic axis is strong; the rendering axis is naked; the triage ledger is decaying.

- **Solver suites are real** — byte-identical determinism, rank monotonicity, overlap-freedom, pinned goldens (flow_solver_golden.rs 1,186 lines; interaction 1,214; stress goldens) — but depth is ~10%: 20/206 solve/ fns reached by tests; `vpsc::project` (cx 67), `stress::reduce_crossings` (cx 51), route `nudge`/`hub_spread`/`astar` all untested. A regression that stays inside the invariants but degrades quality sails through, and already did once: fd8f305f, repair phases silently undoing connector rules, caught only by eyeball.
- **Rendering has no gate at all.** The only pixel-diff tool is scripts/check-use-case-diagram-screenshots.ps1, referenced by no workflow; the in-CI "screenshot" test asserts baseline PNGs merely *exist* (tests/ui.rs:22). To be precise about the platform story: the full workspace test/clippy/build matrix *does* run on windows-latest by explicit design (ci.yml:21-24, with a comment citing past cross-platform escapes), so the native D3D11 editor is compiled and unit-tested on Windows every run. What is Linux-gated is the end-to-end layer: all four UI scenarios (ci.yml:101, :108) and any future pixel comparison. The real gap, stated exactly: **zero E2E and zero pixel coverage on the primary development platform** — the platform whose regressions (cursor leaks, DComp, wheel deltas) have repeatedly required manual catch.
- **The fuzz workflow is dead** **(verified: last two scheduled runs failed in 25-27s)** — and the failure is compound, not a one-line flag. taiki-e/install-action binstalls a musl-hosted cargo-fuzz binary (fuzz.yml:40-43 never mentions musl; the tool brings it) which then targets x86_64-unknown-linux-musl, hitting *both* "sanitizer is incompatible with statically linked libc" *and* "can't find crate for core / the x86_64-unknown-linux-musl target may not be installed" within the same second. Passing `-C target-feature=-crt-static` alone would still fail on the missing musl std; the correct fix is forcing cargo-fuzz to build/run for the gnu host target (or building cargo-fuzz from source). Meanwhile issues.md documents open fuzz-reachable DoS behavior in the exact covered code (inline.rs quadratic adversarial runs). Even when green: 300s/target weekly with the discovered corpus thrown away every run.
- **issues.md is decaying into fiction** **(verified: frozen at cb64c9c0, 2026-08-05)**. It lists as open a nesting-overflow P1 that is fixed in code (FRONTMATTER_MAX_NESTING_DEPTH guard + dedicated suite) right next to the FieldEdit P1 that is verifiably still live: `Unchanged | Clear => serialize_none()` and deserialize `None => Clear` **(verified, uml/ops.rs)** — a wire round-trip silently converts "don't touch this field" into "delete this field." Silent data loss, 16+ days old, one-test fix, unwritten.
- **The performance ceiling is not the parser — it's the analysis behind it, per the project's own open P2.** Every edit triggers bundle-wide semantic reanalysis: okf/shell.rs:208-237 traverses all documents per OKF projection; uml/analysis.rs:161-260 revisits every claimed concept; uml/analysis.rs:509-510, :596-860, :1095-1103 rebuild global validation and projection (issues.md:455-475). Incremental parsing feeding non-incremental analysis pays for the hard half and discards it — for the stated large-bundle ambitions this dominates the parser's Ω(n) floor by construction. The ledger's own first recommendation — repeatable 1/100/1,000-document *edit* benchmarks — was never done; benches/ remains cold-parse only.
- **CI ordering repeats a known failure**: the doc-contract step runs before code compiles under test, the exact configuration that already masked CI for 3 days — and (see §2) the contract's gate is itself the diagnostics-swallowing `check` path, so it is doubly weaker than it looks. PR CI wasm-checks only waml + waml-ops-dto; waml-editor is first built for wasm post-merge at deploy time — a wasm-breaking editor change passes PR CI and breaks main's deploy.
- **Panic and dead-code hygiene**: 110-116 unwraps in the adversarial-input UML island parser (uml/syntax/parser.rs), content-reachable expects at okf.rs:1845/1882, no catch_unwind at LSP/wasm entry points. ~170-190 `#[allow(dead_code)]` sites (count varies by crate scope) systematically defeat the `-D warnings` gate the project pays for — including a blanket allow on the central `DocView` trait itself (doc_view.rs:620), and known-dead machinery kept compiled: the Peek dock state machine ("no production sender any more," dock.rs:8-9), popup/radial.rs (1,025 lines, 19 allows, superseded by MenuPopup), node_design_editor.rs (1,692 lines, harness-only).
- Property testing is asymmetric: 9 proptest blocks all in parser/envelope layers; the edit-op layer — the code that rewrites user documents — is example-based only. No `reparse(write(apply(doc))) == apply` property exists for the highest-stakes invariant in the product.

## 4. Product

### What this is
A solo-built (2,833/2,833 public commits), 260k-line bet that repo-native Markdown knowledge + UML deserves first-class tooling: per-classifier diffable Markdown files, diagrams as curated views, a zero-install web reader with share-URL persistence, a CLI, an LSP stub, and a native editor on a forked pre-1.0 UI framework. The wedge is real and differentiated — nothing in the Mermaid/PlantUML/Structurizr/Obsidian set does "reviewable model in the PR + zero-install reader" as one loop, and the layout solver attacks exactly the problem Mermaid is notoriously bad at.

### What state it is in
Pre-alpha by its own scoreboard: every MVP area "partial," zero "done" (docs/waml/goals/mvp.md). No releases, no tags, no installer **(verified)**; the VS Code extension is `version 0.0.0, private: true` with no publisher **(verified)** — structurally unpublishable. The only distribution that exists is the web editor on Pages — and that reader renders every character of a *knowledge product* into a GPU canvas: no screen-reader accessibility, no browser Ctrl-F, no text for search engines to index **(verified: site.rs:1-10 — the site is the embedded wasm editor plus bundle.waml; a case-insensitive grep for accessib/a11y/screen-reader across the editor source and goal tree yields exactly one hit, a keyboard-shortcut goal line)**. The custom in-app search index exists precisely because the browser's own text machinery cannot see the content. GitHub's native mermaid — the actual competitor — ships accessible, searchable, indexable HTML for free. Given that the source format is literally Markdown, a plain-HTML export is trivial relative to everything else built here, and it is missing. The last month was ~2,075 commits of breadth-first feature accretion (Mermaid rendering via a pinned alpha crate, book mode, classifier pages, use-case diagrams, transition traces, zoom, search) while the #1 roadmap item — truthful diagnostics — saw no commit that implements it. Ten-plus landed features owe visual sign-off, tracked only in agent session memory. 74 active plan files vs 114 completed, including a fully-specified, fully-unstarted atproto/automerge collaboration plan that contradicts the MVP's own deferral list. 65 local branches (50 already merged), 10 stashes, root-level log residue.

### The unasked question
There is no external user anywhere in docs/. docs/waml/user.md defines User as "a person who opens a WAML bundle to read it"; root-goal.md makes the first user the project's own documentation, by design. No persona, no adoption path, no confrontation with the actual competitor: free ```mermaid``` fences rendered natively by GitHub, zero install for author and reader — and accessible to every reader, which WAML's output currently is not. Meanwhile the strongest available 2026 positioning sits unclaimed in the spec WAML builds on: OKF's entire motivation is knowledge "continuously written and maintained by agents" (docs/specs/OKF_SPEC.md §1), and one-file-per-classifier diffable models are the ideal agent-writes/human-reviews substrate. The goal tree never mentions agents; "Beyond UML" targets "an internal wiki" — the most crowded market imaginable.

### MUST KEEP
- waml + waml-syntax core and its entire test regime (goldens, proptests, conformance fixtures, committed regressions).
- The projection/chain system, the edit/undo model, the session/revision model.
- The Pages deploy + `waml export site` pipeline — the closest thing to a finished product, once it grows a text surface.
- issues.md, the goals scoreboard, and the CI doc contract (once reordered *and* re-gated on truthful diagnostics).
- The six-surface editor loop and the shell/view seam.

### MUST FINISH
1. **Truthful diagnostics** across CLI/LSP/editor — one aggregate stream on PreparedCandidate that carries analysis errors *and* quarantined shell-failed documents as first-class diagnostics; error distinct from empty-valid; kill validate.rs's `unwrap_or_default()` and the two `return Vec::new()` compat arms; widen the `check` projection beyond `uml().diagnostics`. This is roadmap item 1 in the project's own ledger; the failure is scheduling, not analysis. Expect the fix to surface a wave of latent doc-contract failures in docs/waml — plan for it rather than discovering it.
2. **The FieldEdit wire round-trip fix** — P1 silent data loss, one test plus a serde fix.
3. **Fuzz workflow repair** — force cargo-fuzz onto the gnu host target (the binstalled musl tool is the root cause; a `-crt-static` flag alone still fails on missing musl std) or build cargo-fuzz from source; plus red-run notification and corpus persistence.
4. **A distribution** — one tagged v0.x release with a Windows zip, or an explicit MVP amendment saying native install is deferred. Right now the MVP requires an editor no one can obtain.
5. **An accessible text surface for the exported reader** — a plain-HTML export (or HTML text layer) so the knowledge product is visible to screen readers, Ctrl-F, and search engines. Cheap relative to what's built; product-defining while absent.
6. **The visual-verification ledger, in-repo**, burned down or converted into the already-scoped screenshot regression harness. "Sign-off owed" is WIP, not done.
7. **LSP filesystem lifecycle** (didSave/watched files; close currently restores stale disk bytes) — or mark the extension experimental and stop paying its gate cost.
8. **Third-party attribution** — a THIRD-PARTY/NOTICE artifact in the repo and in site.rs's asset list covering the MIT makepad fork and merman. An afternoon's work; a real obligation.

### MUST GO
- Peek dock machinery, popup/radial.rs, stale dead_code allows — one sweep, ~3-4k lines.
- node_design_editor + the src/bin harnesses out of the shipping binary (feature-gate or separate crate).
- The atproto collab plan out of the active plans directory (icebox it or promote it — the ambiguous middle is the worst state).
- 50 merged branches, stale stashes, lsp-demo/ at repo root, .test_out5.log.
- The false doc claims: waml-syntax's "domain-neutral" headline, okf.rs's "mechanical split" promise (until made true), analysis.rs's "consumers surface these" quarantine promise (until made true), waml-editor's "read-only viewer" description.

### Strategy calls being avoided
1. **Who is the user?** No document answers it. If the honest answer is "agent-authored architecture docs reviewed by humans," the goal tree should say so and cut everything that doesn't serve it — WAML already has the provenance/freshness/doc-contract machinery that story needs.
2. **Which artifact is the product?** Native editor (needs installer, releases, image export), or format+CLI+LSP with VS Code as the authoring surface and the web reader as distribution? The current path builds the hardest artifact for an unsourced audience — and the reader half of the loop is currently inaccessible by construction.
3. **The fork's endgame.** Upstream aggressively (per-Cx tree, headless backend are generally useful) or declare it permanent with its own CI. The current implicit position — hand-tracking a fast-moving upstream while carrying patches it may never accept, one person paying every rebase, every build routed through one personal GitHub account with no audit tooling — is the worst one. The fork's payoffs (one codebase native+wasm, SDF-crisp rendering) are real; its taxes (5,693 lines of hand-authored icon splines, a bespoke UI-test harness, weeks lost to shader boots and zoom framerates) are also real. Freeze new fork scope until an MVP area moves to "done."
4. **Diagram interop.** No mermaid/plantuml import or export and no SVG/PNG export exist anywhere — the product's visible value cannot leave its own toolchain, so the "no lock-in" story is only true for prose. One-way mermaid export is cheap and is the strongest possible on-ramp argument ("you can always leave").
